# ROB RUN AutoClicker

A Windows utility for **ROB RUN**: while you hold **Ctrl** and the **left mouse button**, the app automatically emits left clicks at a configurable interval. It is useful for repetitive actions that require left-clicking without pressing the button manually dozens of times per second.

The app uses only the Windows input API (`WH_MOUSE_LL` + `SendInput`). It does not read game memory, inject DLLs, patch game files, or access the network.

> **Important:** in the default `intercept` mode, physical LMB down/up events are suppressed while the auto-clicker is armed, and all clicks are generated by the app. This prevents duplicate clicks. If the game does not react to injected clicks, try `passthrough` mode or run the app as Administrator.

> **Download:** the latest executables are available from [GitHub Releases](https://github.com/sebastianmeet/robrun-autoclicker/releases/latest). The public repository contains the source code; `dist/`, `.venv/`, and build files are not versioned.

---

## What it does

- **Trigger:** physical Ctrl + physical LMB held together. Recommended: press **Ctrl** first, then **LMB**.
- **Clicks:** clean `LEFTDOWN` + `LEFTUP` cycles at `interval_ms` ± `jitter_ms` (default 25 ms ± 5 ms, approximately **40 clicks/second**).
- **Immediate stop:** when Ctrl or LMB is released, when the game loses focus (with `only_in_game=true`), or when the exit hotkey is pressed. The worker checks state every ~5 ms, and the synthetic button is always released at the end.
- **Game-only mode:** with `only_in_game=true`, clicks are emitted only when the foreground window belongs to the process configured in `game_process` (default `ROB RUN.exe`).
- **No feedback loops:** injected events are ignored by the hook (`LLMHF_INJECTED` / `LLMHF_LOWER_IL_INJECTED`), and every synthetic event carries `dwExtraInfo = 0x5255434C`.
- **Shutdown safety:** on any normal shutdown, if a synthetic `LEFTDOWN` is still active, a final `LEFTUP` is sent. The hook is removed and the single-instance mutex is released.
- **Single instance:** launching a second copy shows a clear message and exits.
- **No console in release:** `RobRunAutoClicker.exe` runs silently. `RobRunAutoClicker-debug.exe` has a console and prints state transitions.

### Trigger modes

| Mode | Behavior |
|---|---|
| `intercept` (default) | While the arming condition is met, the hook **suppresses** physical LMB down/up events and only the worker generates clicks. This is the recommended mode. |
| `passthrough` | The physical click reaches the game, and synthetic clicks are added on top of it. Use this if intercept mode does not work in the game. It may produce one extra click at the start of the gesture. |

## Files and requirements

- Windows 10/11 x64.
- **Python is not required on the machine running the `.exe`.**
- To run the app, only the files in `dist/` are needed (downloaded from GitHub Releases or generated locally):
  - `RobRunAutoClicker.exe` — release build, no console;
  - `RobRunAutoClicker-debug.exe` — debug build, with console;
  - `config.json` — must be placed **next to** the executable;
  - `README.md`.
- Configuration is read only at startup. After editing `config.json`, restart the app.
- If `config.json` is missing, it is recreated with default values in the executable's folder. The folder must be writable (avoid `C:\Program Files` without administrator rights).

## Configuration

File: `config.json`, in the same folder as the `.exe`.

| Key | Default | Meaning | Range / valid values |
|---|---:|---|---|
| `interval_ms` | `25` | Target interval between the starts of two click cycles. | Integer, `5`–`500` ms |
| `jitter_ms` | `5` | Uniform random variation applied to each interval: `±jitter_ms`. | Integer, `0`–`100` ms |
| `only_in_game` | `true` | When `true`, clicks are emitted only while the foreground process is the one configured in `game_process`. | `true` / `false` |
| `exit_hotkey` | `"Ctrl+Alt+F8"` | Global hotkey that stops the app cleanly. | Modifiers: `Ctrl`, `Alt`, `Shift`, `Win`; key: `F1`–`F24`, `A`–`Z`, `0`–`9`, or common keys (`Esc`, `Space`, `Tab`, `Insert`, `Delete`, `Home`, `End`, `PageUp`, `PageDown`, arrow keys). One key plus modifiers. |
| `trigger_mode` | `"intercept"` | How physical clicks are handled. | `"intercept"` or `"passthrough"` |
| `game_process` | `"ROB RUN.exe"` | Game process name. Comparison is case-insensitive and uses the basename. | Non-empty text; exact name from Task Manager → Details |
| `debug_log` | `false` | In the release build, enables writing to `RobRunAutoClicker.log` next to the `.exe` (when no console is available). The debug build always logs to its console. | `true` / `false` |

Example:

```json
{
  "interval_ms": 25,
  "jitter_ms": 5,
  "only_in_game": true,
  "exit_hotkey": "Ctrl+Alt+F8",
  "trigger_mode": "intercept",
  "game_process": "ROB RUN.exe",
  "debug_log": false
}
```

Validation: invalid or missing values are replaced with defaults, and the app shows a clear message (console in the debug build, message box in release). An invalid file is not overwritten automatically. `interval_ms` is the time between cycles, not how long the button is held; each `LEFTDOWN` is held for ~3 ms before `LEFTUP`.

> If ROB RUN runs as a Roblox application, the game window may belong to `RobloxPlayerBeta.exe` rather than `ROB RUN.exe`. Check the name in Task Manager and set it in `game_process`.

## How to run

1. Open the `dist/` folder.
2. Check `config.json`. For the browser test, temporarily set `"only_in_game": false`.
3. Double-click `RobRunAutoClicker.exe`.
4. (Optional, recommended if ROB RUN does not receive clicks) right-click the executable → **Run as administrator**. An administrator manifest is intentionally **not** included.
5. Open ROB RUN, hold **Ctrl**, then hold the **left mouse button** and use the generated clicks.
6. To stop the app: **Ctrl+Alt+F8** (or the configured hotkey).

### SmartScreen and antivirus

- On first launch, Windows SmartScreen may show "Windows protected your PC". Click **More info → Run anyway**. This is normal for unsigned PyInstaller executables.
- An antivirus may report a **false positive** for auto-clickers / PyInstaller onefile executables. Do not disable protection; add an exception only for the `dist/` folder if you trust the source and verify the hash.
- The executables are not digitally signed. For public distribution, they should be signed with a code-signing certificate.
- Run as Administrator only when needed (UIPI): a non-elevated process cannot inject input into an elevated game/console and may be unable to read the foreground process name.

### Runtime notes

- Do not start two instances: the second one shows an "already running" message and closes.
- If you move the `.exe`, move `config.json` next to it as well.
- Launch the debug build from a console:
  ```powershell
  .\dist\RobRunAutoClicker-debug.exe
  ```
  You will see lines such as `[STATE] START`, `[STATE] HOOK installed`, `[STATE] ARMED`, `[STATE] CLICKING`, `[STATE] STOPPED reason=Ctrl released`.
- The release build has no console. With `"debug_log": true`, it writes `RobRunAutoClicker.log` next to the `.exe`.

## Manual test

Open `tests/click-counter.html` in a modern browser (Chrome/Edge/Firefox). The page counts left-button `mousedown` events and shows the total and clicks/second over a 2-second window. **F2** resets the counter without using the mouse. Note: with `only_in_game=true`, when the browser is in the foreground, the physical click passes through the hook and is counted; that is why the test uses F2 to reset while holding Ctrl+LMB.

1. **Click rate**
   - Set `"only_in_game": false` in `config.json`, save it, and start `RobRunAutoClicker.exe`.
   - Focus the test page.
   - Hold **Ctrl**, then hold **LMB** over the page.
   - **Expected result:** the counter increases continuously at approximately **35–45 clicks/s** (default 25 ms ± 5 ms). Physical clicks are suppressed in intercept mode.
2. **Immediate stop**
   - While the counter is increasing, release only **Ctrl**; then repeat and release only **LMB**.
   - **Expected result:** clicks stop immediately (within ~50 ms), with no values continuing to increase. No mouse button remains pressed.
3. **Game-only mode**
   - Set `"only_in_game": true`, save, and restart the app.
   - Focus the test page (or another application), hold Ctrl, press LMB (the physical click appears in the counter), then press **F2** while holding Ctrl+LMB.
   - **Expected result:** the counter stays at `0` and CPS stays at `0.0`; the auto-clicker does not emit clicks while the browser is in the foreground. There are no repeated clicks.
4. **In ROB RUN**
   - Open the game, choose a safe area/target (not an important action), hold **Ctrl**, then **LMB**.
   - **Expected result:** clicks are generated rapidly while both inputs are held. Start with a longer interval if you want to check how the game behaves.
   - If it does not work, see Troubleshooting (Administrator, borderless, process name, passthrough).
5. **Exit and mouse state**
   - Press **Ctrl+Alt+F8**.
   - **Expected result:** the process exits within one second, the hook is removed, any synthetic `LEFTDOWN` is followed by `LEFTUP`, and normal physical clicking works immediately afterward. You can relaunch the app (the mutex was released).
6. **Automatic config**
   - Temporarily rename `dist/config.json` and start the exe.
   - **Expected result:** `config.json` is recreated with default values and the app starts normally. Stop it with Ctrl+Alt+F8 and restore the file if you had custom settings.
7. **Second instance**
   - While the first instance is running, start the exe again.
   - **Expected result:** an "already running" message appears; the new instance closes and the first one stays functional.

## Troubleshooting

### No clicks in ROB RUN

- **Run as Administrator.** A normal process cannot send input to an elevated window (UIPI). Right-click → **Run as administrator**.
- **Try borderless / windowed mode**, not exclusive fullscreen. Some games and overlays ignore or filter injected input in exclusive fullscreen.
- Check `only_in_game`: when `true`, the foreground process must exactly match `game_process`. Open **Task Manager → Details** and confirm the name. For Roblox, the name may be `RobloxPlayerBeta.exe`; for the standalone app, it may be `ROB RUN.exe`.
- First confirm that the app generates clicks: set `only_in_game=false`, start the debug build, and test with `tests/click-counter.html`. If that works, the problem is in the game (focus/UIPI/fullscreen), not the worker.
- **Intercept vs passthrough:** if the game does not react at all in `intercept`, set `"trigger_mode": "passthrough"` and restart. In passthrough, the game receives the physical click plus the synthetic clicks; this is a fallback, not the first choice.
- Close other auto-clickers, macros, or utilities that install mouse hooks; they can interfere with this hook.
- Check your antivirus: it may block `SendInput` or the hook. Use the debug build for error messages.

### Checking the process name

```powershell
Get-Process | Where-Object { $_.MainWindowTitle -ne "" } |
    Select-Object ProcessName, MainWindowTitle
```

Find the ROB RUN window and note its `ProcessName`. In `config.json`, add the `.exe` extension to the name: for example `"ROB RUN.exe"` or `"RobloxPlayerBeta.exe"`.

### SmartScreen / antivirus

See the **How to run** section. PyInstaller executables may be reported as false positives. Do not disable antivirus protection; add a targeted exception only if you have verified the source. For distribution, sign the executables.

### Hotkey conflict

- The default is **Ctrl+Alt+F8**. If it conflicts with another program, change `exit_hotkey` to a valid combination, such as `"Ctrl+Shift+F10"`.
- The hotkey is global and works regardless of the active window.
- Do not use combinations reserved by Windows (for example `Ctrl+Alt+Del`).
- If the app does not exit, check whether an older instance is still running (Task Manager).

### Verifying the process is running

Open **Task Manager → Details** and look for `RobRunAutoClicker.exe` or `RobRunAutoClicker-debug.exe`. The release build has no visible window; the debug build has a console. You can also check from PowerShell:

```powershell
Get-Process RobRunAutoClicker, RobRunAutoClicker-debug -ErrorAction SilentlyContinue
```

### Mouse appears stuck after stopping

The app sends a final `LEFTUP` on every normal shutdown (including Ctrl+Alt+F8). If Windows still reports the button as pressed, click the physical left button once; this is rare and usually happens after force-terminating the process (Task Manager / crash) exactly between `LEFTDOWN` and `LEFTUP`. Do not force-kill the process if you can use the hotkey.

### Invalid configuration

The app uses defaults for invalid fields and displays a message. In the console-less release build, the message appears as a message box. Fix `config.json` and restart. The file is not overwritten automatically.

### Known limitations

- Clicks are sent to the current cursor position. With `only_in_game=true`, the check is based on the foreground window's process; overlays or windows appearing above the game can change the target.
- It does not work over the Windows lock screen, UAC prompts/secure desktop, or in games that completely filter injected input.
- It cannot guarantee that the game or anti-cheat systems will accept the clicks. Verify manually and follow the game's rules.
- Force-terminating the process (kill) can interrupt the button-release sequence; use Ctrl+Alt+F8.

## Building from source

Requirements: Windows x64, **Python 3.11+** on PATH, and an internet connection to install PyInstaller. The app has no runtime dependencies outside the Python standard library.

```powershell
git clone https://github.com/sebastianmeet/robrun-autoclicker.git
cd robrun-autoclicker
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

The script:

1. checks the Python version;
2. creates/reuses `.venv`;
3. installs `requirements-build.txt` (PyInstaller only);
4. builds:
   - `dist\RobRunAutoClicker.exe` — `--onefile --noconsole`;
   - `dist\RobRunAutoClicker-debug.exe` — `--onefile --console`;
5. copies `config.json` and `README.md` into `dist/`;
6. prints the absolute paths of the resulting files.

`config.json` is **not** bundled into the executable: it remains editable next to the `.exe`. On rebuild, `build.ps1` overwrites `dist\config.json` with the one in the project root, so keep your settings in the root `config.json` if you want to preserve them.

Unit tests for configuration validation:

```powershell
python -m unittest discover -s tests -v
```

Source structure:

```text
robrun-autoclicker/            # GitHub repository
├─ main.py                     # hook, worker, config, hotkey, single instance
├─ config.json                 # editable settings, copied next to the .exe
├─ build.ps1                   # release + debug build
├─ requirements-build.txt      # PyInstaller (build only)
├─ tests/
│  ├─ test_config.py           # unit tests for config
│  └─ click-counter.html       # local mousedown counter
└─ dist/                       # generated locally by build.ps1, ignored by Git
```
